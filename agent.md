# Working rules for this repository

## What lives here

- The overview page (`overview/`, built into `docs/index.html`) and the shared demo world and screenshot tools (`demo/`).
- Kante, Knust and the Kimai plugin kit live in their own repository, [shrippen/Kante](https://github.com/shrippen/Kante) (checkout `../Kante`). Design changes go there, never into `docs/v1/` here; see Kante's `agent.md` and `AGENT-RULE.md`.
- `./build.sh` copies `../Kante/docs/v1/` unchanged into `docs/v1/` (served at `https://shrippen.github.io/v1/`, linked by every landing page) and builds the overview. Run it after every change to Kante or to `overview/projects.json` and commit `docs/`.

## Release rule (all projects)

- Every release gets a detailed release log with graphics: a lead, the changes grouped as New, Improved, Fixed and Note, each point with what changed for the user and why; a demo screenshot per visible change (every language of the page), a diagram for changes inside.
- The log goes into the release notes on Gitea and as the newest entry of `#changes` on the project's landing page (Kante `.changelog`, 1.17). A release is done when the landing page shows it. Details: `overview/PROJECTS.md`.

## Repository rule

- This repository lives on Gitea (`git.arianw.de`). GitHub is only a push mirror of it.
- Changes arrive as pull requests: work on a branch, open a PR, merge it on Gitea (the mirror follows).
- Never merge a PR, push to `main` (or any default branch), push tags or publish releases on GitHub. A merge there is overwritten by the next Gitea push.
- Never force-push a branch that someone else's PR depends on.
- Claude may merge its own PRs on Gitea after a clean `./build.sh` (this repository has no CI; decision G-07 in Kaiwa) and the Claude review leaves no **Wichtig** open (see below).
- Claude review (all shrippen repositories, owner 18.10.2026): every PR is reviewed by a new Claude agent before it is merged. The owner does not read code, so this is the second reader.
  - The session that wrote the PR starts a new agent (Agent tool, no shared context) and gives it only the PR's title and body, the diff against its base (`git diff <base>...HEAD`), the repository and `REVIEW.md`. It does not tell it what it thinks of its own change.
  - The agent checks every finding it would post against the code (file, line, the input that goes wrong) and drops what it cannot show. It reports as `REVIEW.md` says: count first, labels **Wichtig**, **Kleinigkeit**, **Bestand**.
  - The session posts the report unchanged as a PR comment on Gitea. Above it goes the heading `## Claude-Review (neuer Agent) zu <commit>`, below it the footer `---` and `_Generated by [Claude Code](https://claude.ai/code)_`.
  - Each **Wichtig** is fixed, or answered in the PR with a reason. An answer counts only when the next review agent accepts it; if it does not, the owner decides in words.
  - After a fix or an answer, a new agent gets the PR's title and body, the open **Wichtig** of the last round with the answers, and only the new commits (`git diff <last reviewed commit>..HEAD`; without new commits, the code at HEAD). After a rebase or a merge of the base it gets the whole diff again. Every round counts, also one with answers only: after three rounds that still leave a **Wichtig** open, stop and rethink the approach with the owner.
  - Merge only when the last review covers the PR's latest commit and has no open **Wichtig**, and the checks are green: every CI check that runs for the PR's commits is success on the newest commit it ran on; a check that has not reported yet means wait, not merge. Without CI, the local checks of the merging rule count.
  - Before the merge, the owner confirms in words, not by reading code, a PR that changes CI or release workflows (`.gitea/`, `.github/`, `packaging/`), this review rule (`agent.md`, `REVIEW.md`), secrets or what is published.
  - `REVIEW.md` in the repository root says what failure looks like here, what to check in particular, what to skip and how to report. A repository without one gets it in its next PR.
- PR-Agent (where set up) is an extra reader: read its findings and fix or answer them like the Claude review's. If it fails, ask once more with `/review` (it runs only for comments from the owner's account `shrippen`); if that fails too, or nothing answers, the Claude review and green CI are enough.
